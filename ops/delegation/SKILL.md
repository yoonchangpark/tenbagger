# 작업 위임 (코디네이터 → 스레드)

**목적**: 스레드에 일을 맡길 때 겹침·규칙 위반·권한 부족을 시작 전에 걸러, 첫 실행에서 맞게 끝나게 한다.

**언제 쓰나**: 오너가 새 일을 말했을 때 전부. 예: "구독 페이지 고쳐줘", "숏츠 소재 더 찾아줘".

**입력**: 오너의 메시지, `MEMORY.md`, 열린 스레드 목록, 열린 PR 목록.

## 단계

### 01 INTERVIEW — 브리프를 채운다
1. 열린 스레드와 열린 PR을 본다. 같은 파일·같은 영역을 만지는 게 있으면 새 스레드 대신 그 스레드에 넘긴다.
2. 아래 브리프를 채운다. 빈 칸이 있으면 오너에게 **그 칸만** 한 번에 하나씩 묻는다.

```
언제 쓰나:   (오너가 실제로 한 말 그대로)
목표:        (무엇이 달라지면 성공인가, 한 줄)
완료 기준:   (밖에서 확인 가능한 문장. "PR 머지"가 아니라 "월요일 리포트에 구독자 수가 찍힌다")
범위 밖:     (손대지 말 것 — 다른 스레드가 쥔 파일·영역)
관련 결정:   (MEMORY.md의 어느 결정을 따르는가)
겹침 확인:   (같은 파일을 만지는 열린 스레드·PR. 없으면 "없음 확인")
오너가 해야 할 일: (대시보드 조작·로컬 실행 등. 없으면 "없음")
업무 폴더:   (ops/<업무>/ — 없으면 이번 작업 끝에 만든다)
```

### 02 MANUAL — 규칙을 읽는다
3. 스레드는 `CLAUDE.md` → 해당 `ops/<업무>/SKILL.md` → 아래 영역 주인 표 → `MEMORY.md` 관련 항목 순으로 읽는다.

| 영역 | 주인 파일 | 규칙 |
|------|----------|------|
| 구독·권한·횟수 제한 | `backend/app/core/auth.py` | 새 모듈·새 테이블 금지, 기존 함수 확장. 시작 전 main 최신본을 읽는다 |
| 요금제 문구 | `api/payment.py` `PLANS`, `frontend/pricing.html`, `frontend/payment/success.html` | 셋을 같이 고친다. 구현 안 된 혜택은 적지 않는다 |
| Threads 발행·큐 | `threads-auto/{publisher,content_queue,devlog_generator,main,scheduler,token_manager}.py` | 발행 담당 외 직접 수정 금지. 접점은 `queue.add(text, image_urls, source_key)` |
| 카드뉴스 | `threads-auto/cardnews/` | 렌더는 로컬. 결과 PNG는 `frontend/media/threads-posts/` |
| 숏츠 소재 | aiva `data/tenbagger_history.json`, tenbagger `v2_shorts_feed.py:CANDIDATES` | DART 실공시로 확인한 숫자만 |
| v1 API | `/api/*` | 시그니처·응답 불변. 새 기능은 `/api/v2/*` |
| CHANGELOG | `CHANGELOG.md` | `.9` 다음은 다음 메이저. 푸시 직전 main과 열린 PR 번호 재확인. `### 배경` + `### 추가/변경/수정` 유지 |
| 스코어링 백필 | `run-factor-eval` | 오너가 다시 요청할 때까지 돌리지 않는다 |

### 03 TOOLBOX — 손이 닿는지 먼저 확인한다
4. 브리프의 "오너가 해야 할 일"이 실행 도중이 아니라 **지금** 드러나게 한다. `files/INDEX.md`의 할 수 있음/없음 표를 본다.
5. 시크릿이 필요하면 값을 채팅에 붙여 달라고 하지 않는다. "Railway → 서비스 → Variables에 `X` 이름으로" 처럼 위치만 안내한다.

### 04 EXECUTE
6. 세션 브랜치에서 작업, 커밋·푸시·드래프트 PR은 자동(CLAUDE.md).
7. 백엔드와 Threads 발행기는 Railway 서비스 하나를 쓴다. 다른 스레드의 배포가 끝나기 전에 머지하지 않는다.

### 05 VERIFY
8. `proof.md`의 공통 체크 + 해당 업무 폴더의 `proof.md`를 돌리고, 결과를 답장에 그대로 붙인다.
9. 되돌릴 수 없는 단계는 이 스레드에서 오너가 직접 쓴 승인이 있어야 한다.

### → 01
10. 틀린 게 나오면 `ops/README.md`의 "매뉴얼을 고친다" 절차를 따른다. 다음 스레드가 오너에게 다시 물어야 할 사실은 `MEMORY.md`에도 적는다.

## 판단 규칙
- 해석이 둘 이상이면 가장 그럴듯한 쪽으로 시작하고, 어느 쪽을 골랐는지 답장에 적는다.
- 오너의 목표를 바꾸는 선택만 오너에게 묻는다. 나머지는 되돌릴 수 있으면 하고 알린다.

## 완료 기준
브리프의 "완료 기준" 문장이 외부 증거로 확인됐고, 그 증거가 답장에 있다.
