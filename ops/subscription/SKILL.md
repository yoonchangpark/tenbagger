# 구독·요금·사용량 게이트

**목적**: 무료로 맛보고 유료로 넘어오게 해서 구독 100명을 만든다.

**언제 쓰나**: "요금제 바꾸자", "이 기능 유료로 막아줘", "구독자 몇 명이야?".

**입력과 위치**: `backend/app/core/auth.py`(등급 판정·횟수 제한), `backend/app/api/payment.py` `PLANS`, `frontend/pricing.html`, `frontend/payment/success.html`.

## 단계
1. **INTERVIEW** — 바꾸려는 것이 가격·혜택·게이트 중 무엇인지, MEMORY의 결정과 부딪히는지 본다.
2. **MANUAL** — 아래 판단 규칙.
3. **TOOLBOX** — 시작 전 `git fetch origin main` 후 **최신** `auth.py`를 읽는다. 결제사 콘솔은 오너만 접근.
4. **EXECUTE** — 게이트는 기존 함수를 확장한다. 문구는 세 곳을 같이 고친다.
5. **VERIFY** — `proof.md`.

## 판단 규칙
- 요금제: Free ₩0 / 기본 ₩5,900 / Pro ₩9,900. 플래티넘 없음.
- AI 횟수: Free 평생 3회(초기화 없음), 기본 기능당 주 3회(월요일 KST 초기화), Pro 무제한.
- **새 GPT 호출만 막는다.** 이미 저장된 결과는 비로그인에게도 보여 준다 → 캐시가 있으면 `allow_cached_or_trial`(PR #119, 아직 머지 전), 없으면 `require_subscription_or_trial`.
- 비로그인 샘플은 서버에서 숫자를 가린다. 분석일과 "무료 3회"를 함께 표시.
- 구현 안 된 혜택은 요금제에 적지 않는다.
- 캐시된 투자위원회 결과 재조회는 횟수를 깎지 않는다.
- 새 게이트 모듈·새 사용량 테이블을 만들지 않는다.

## 완료 기준
가격·혜택 문구 세 곳이 일치하고, 실제 게이트 동작이 그 문구대로다.

## 알려진 차이
- 구독자 수·무료→유료 전환을 보여 주는 리포트가 없다. 목표가 100명인데 현재 몇 명인지 시스템이 말해 주지 않는다.
