# ops/ — 업무별 매뉴얼 폴더

반복 업무마다 폴더 하나. 어느 스레드든 해당 폴더만 읽으면 같은 방식으로 일한다.
전체 개념과 현재 진단은 루트의 `OPERATIONS_MANUAL.md`.

| 폴더 | 언제 쓰나 (오너가 하는 말) |
|------|------------------------|
| `shorts/` | "이번 주 숏츠 소재 채워줘", "숏츠 왜 이상하게 나왔어?" |
| `threads/` | "스레드 글이 안 올라갔어", "다음 주 스레드 큐 확인해줘" |
| `cardnews/` | "이번 변경 카드뉴스로 만들어줘" |
| `subscription/` | "요금제 바꾸자", "이 기능 유료로 막아줘" |
| `delegation/` | 코디네이터가 스레드에 일을 맡길 때 — 모든 작업의 시작점 |

## 폴더 하나의 구성

| 파일 | 층 | 담는 것 |
|------|----|--------|
| `SKILL.md` | Process | 목적 한 줄, 언제 쓰나, 입력과 위치, 번호 매긴 단계, 판단 규칙, 완료 기준, 과거 엣지케이스 |
| `files/INDEX.md` | Toolbox | 쓰는 스크립트·템플릿·데이터의 위치와 용도. 기존 코드는 원래 경로에 두고 여기서 가리킨다. 한 파일 한 목적. 매달 안 쓰는 항목 정리 |
| `proof.md` | Proof | 결과를 보이기 전에 직접 돌리는 체크. **외부 증거(원자료 숫자, 열리는 링크, 통과하는 명령, 글자수)로만 판정** |
| `notes.md` | 기록 | 매뉴얼을 고친 이력: 날짜 · 증상 · 원인 층 · 수정 |

## 결과가 틀렸을 때 — 채팅 말고 매뉴얼을 고친다

1. 원인 층을 가린다. 단계·판단 규칙 누락 → `SKILL.md`. 낡은 자산 → `files/`. 아무 체크도 못 잡음 → `proof.md`.
2. 그 층에 **최소한의 영구 수정**을 하고 `notes.md`에 한 줄 남긴다.
3. 같은 입력으로 다시 돌려 전후를 비교한다.
4. **첫 실행에서 proof 체크가 2개 넘게 실패하면 결과물을 고치지 말고 `SKILL.md`부터 고친다.**
